What this project is

A reviewable browser-testing platform for an existing ecommerce site.

TestOps lets a team register a target, define suites and cases, queue browser work, and inspect a durable history of what happened. The target website is deliberately kept outside TestOps’ ownership boundary: TestOps controls the test definition, safety policy, worker, and evidence; the ecommerce application owns its own catalog, account, checkout, and messaging behavior.

How to use this report: start with the user manual if you want to operate the app, the API handbook if you need to call it, the architecture page if you need the system boundary, and the code guide if you need to change it.

Important vocabulary

DRAFT
A case that may be incomplete and can be edited without being executable.
READY
A case whose steps satisfy the executable definition rules.
Target health
The last sanitized result of checking the project’s approved origin.
Execution snapshot
The immutable target, case, step, browser, and variable-reference data captured when a run is queued.
Infrastructure error
A worker, browser, target, timeout, or policy problem—not a failed business assertion.
